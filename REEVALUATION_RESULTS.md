# Reevaluation and new experiments

## Wheel 1 on the archived test

We evaluated the 78 original models on their original inputs. Each reevaluation figure is the percentage of correct individual pin predictions across all 26 wheel-1 pins and all 102,976 archived test keys. This gives 2,677,376 predictions per length. The published figures are shown for comparison.

| Input length | Published figure | Original 2024 models | New models, corrected inputs |
|---:|---:|---:|---:|
| 52 | 71.91% | 71.56% | 75.26% |
| 104 | 88.40% | 88.16% | 88.63% |
| 200 | 96.71% | 96.62% | 96.50% |

For each length, we trained one model for each of the 26 wheel-1 pins for ten epochs and evaluated the final-epoch model. Relative to the reevaluated original models, the differences are +3.70, +0.47 and -0.12 percentage points. These comparisons can also reflect training variability and the incompletely documented historical training settings. They are not an estimate of variability across training seeds. [Results for every pin](results/wheel-1-per-pin.md) and [recalculated counts](results/wheel-1-rescoring.json) accompany the table.

### Corrected-input comparison

For lengths 52 and 200, we keep the published model hyperparameters and amount of training data, and correct the displacement extraction. For length 104, we also use the same training-data amount as for length 200. The corrected call in [notebook #4](Tools/%234_train_models.ipynb) is `load_partial_data(100,15000)`. The published cell requests only 10 files with up to 1,500 rows each, although the saved log for length 104 records 100 files loaded. The original row limit per file is unknown. We keep the other settings in the length-104 cell, including 26 filters and a batch size of 260.

| Input length | Files per attempt | Maximum rows per file | Maximum rows used for fitting per model |
|---:|---:|---:|---:|
| 52 | 100 | 10,000 | 640,000 |
| 104 | 100 | 15,000 | 960,000 |
| 200 | 100 | 15,000 | 960,000 |

The notebook reserves 20% of the loaded rows for the internal test and 20% of the remainder for validation. At every length we keep the architecture, optimizer, learning-rate schedule, batch size and ten-epoch training budget from that length’s published training cell. All 26 wheel-1 pins are included explicitly. The runtime is Keras 3 with the Torch CUDA backend, FP32 with TF32 disabled; deterministic per-epoch shuffling allows checkpoint resume. This differs from the historical TensorFlow environment.

For archived all-A sequences we skip the ten indicator-derived values once and take the next 52, 104 or 200 displacements. With data generated by the corrected exporters, the first value is already a payload displacement. Evaluation uses the same 102,976 archived test keys, labels and per-key weighting as the reevaluation of the original models. Each headline score covers all 26 wheel-1 pins.

**Status on 24 November 2026.** Training and evaluation are complete for all 26 wheel-1 pins at each of the three lengths. The length-104 run used 960,000 fitting examples per model and finished on 24 November at 03:46 CET. Its final mean is 88.63%.

Archived-test scores were never used to select checkpoints or models. The original archived training pool was used throughout; only the 190 complete-size file pairs were eligible. Full pin patterns were checked for duplicates and overlap with the archived test keys before fitting, with none found in the selected data.

**Effect of training-data size.** In a separate two-pin pilot at length 104, increasing the fitting set from 960,000 to 1,280,000 examples per model raised mean test accuracy from 89.66% to 90.25%, about 0.6 percentage points. These scores used the same archived test keys and the pilot’s validation-based stopping rule. The tested increase gave a modest gain. We have not established a data size beyond which accuracy stops improving.

The [verified counts](results/first-pass-verification.json) and [training and artifact manifest](results/corrected-training-results.json) document the three runs in the main table. The pilot above is separate from that comparison. The exact run behind the published Table 1 is still unknown. Notebook #8 records 99,903 cases in its saved per-class table.

## Public indicators

The separate operational experiment uses consistent indicator-derived message starts and relative pin labels. Its indicator comparison holds the amount of payload information fixed and compares genuine indicators, indicators from another message, and no indicators. The sampled results show no consistent benefit across lengths.

## Reproducible evidence

**New wheel-1 models trained on 52, 104 and 200 corrected displacement values** — [archive link or DOI if shared].

The new training ran sequentially on one NVIDIA GeForce RTX 4070 Laptop GPU with 8 GB of memory. The [manifest](results/corrected-training-results.json) records the settings, data selections, per-pin counts and model/prediction SHA-256 hashes. Model weights, prediction arrays and detailed logs are retained locally; the large binary files are not part of this PR.

From the repository root, reconcile all reported counts with:

```sh
python Tools/verify_reevaluation_results.py
```

With the retained artifact directories and the archived `y.npy`, verify the raw predictions and model files as well (requires NumPy):

```sh
python Tools/verify_reevaluation_results.py --labels path/to/y.npy --artifacts-root path/to/artifacts --verify-models
```
